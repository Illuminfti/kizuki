# World read implementation amendment

Status: Proposed for independent review and integration, 2026-09-21. This is an implementation amendment to D22's minimal slice, not a claim of historical owner acceptance. The full D21 launch requirements remain open.

The useful read path requires bounded `find_concepts` and `find_situations` discovery in addition to exact `concept` and `situation` reads. Discovery uses admitted, currently authorized classifications and labels, never guessed tokens or name-based identity merging. A raw endpoint gets a random internal handle in the existing shared claim/support transaction, with an allocation receipt and exact support membership. No handle stores type, label, confidence, or truth. Homonyms remain separate; alias merge/separation is not implemented by this slice.

Ledger32 persists handle bindings and allocation receipts plus principal/grant-bound random wire references. The supported wire kinds are object, claim, admission, event_version and principal. All resolve through typed foreign-key targets and current policy; references carry no authority. Grant changes rotate only that principal's namespace. Source revocation is checked on every read; physical deletion removes dependent references and unsupported handles. Rebuild does not synthesize new random identities. Backup/v3 at ledger32 requires these streams and preserves valid owner mappings; agent enrollment is nonportable and unmatched agent namespaces are discarded on restore; this does not adopt proposed backup6 or its unrelated lifecycle contracts.

Read results use `kizuki.world-view/v1`, an operation discriminator and the RFC's current/incomplete/unavailable result. Complete fresh reads use `view:{status:"not_issued"}`. No view-token, resume, history, diff or conditional capability is advertised. Historical requests return unavailable/history. Coverage states unavailable history and any observed bounded traversal loss. The existing ConceptCard and SituationCard schemas remain the semantic result codecs.

Minimal Situation vocabulary is world.kind=world/situation, situation.label, situation.objective, situation.participant, situation.commitment, situation.blocker and situation.change. Its semantics are qualified assertions, not a task execution or second writer API. Existing claim semantics survive corrections as new superseding claims. Capture remains model-free; interpreted claim production still requires its existing authorized producer path.

Verification must cover a real admitted source through shared writer and CLI/MCP reads, current source and principal policy, time windows, correction, restart, schema migration, backup/restore, purge, and rebuild. These implementation receipts do not establish model extraction quality, two-client resume, human stranger qualification, or launch readiness.

The existing support table gains a closed support_origin arm: source (ledger31 default) or native_owner. Native owner contributions retain the private reserved source encoding native-owner/0, but that spelling grants nothing: Core verifies the immutable native correction record, event identity and absence of external source binding. The source arm cannot use the reserved key. The support-key hash uses a separate internal domain for native contributions. The hashes never become wire references. Native correction needs its own evidence, rather than anchors on an external statement that says something different.

New qualified world meanings use the separate private kizuki.claim-meaning/v1 codec in the existing semantic payload column. It contains no source spans. All original anchors and attributed rendering stay in individually erasable, checked WorldAdmission children. Historical generic v2 payloads retain their original decoding. Erasing an event erases its whole affected contribution and wire mappings; the neutral parent provenance is rebuilt only from complete surviving contributions (current policy is evaluated separately at read time). Independently supported meaning survives without keeping the erased source's spans. A corrected assertion has a new immutable meaning and independently grounded native contribution; it does not mutate the old assertion.

The world_view tool alone uses the RFC envelope/v2 field set and typed principal ref. Existing nine tools retain their compatibility contracts; this implementation does not claim to have finished their separately required v2 migration. World output never emits denied counts or global policy epochs.

Ledger32 also persists bounded occurrence identity snapshots. Connector and source record ID are reconstructed from the immutable event; the stored event revision, origin binding, accepted time, resolved source and UTF-16 span must reproduce the canonical mint tuple. Supplied IDs must be present in cited immutable event subjects. Occurrence identity is distinct from semantic handles and is removed with its event or last allocated binding. A permanent `claims.is_world_typed` discriminator separates semantic-key idempotency from legacy body-key idempotency, allowing genuinely empty legacy bodies for typed claims.

Discovery's optional label is a Unicode case-sensitive substring filter. Classification and label candidates are filtered by current support authorization before the application limit. SQLite index work can grow with stored data; this slice bounds parsed support bytes, application materialization, returned matches and durable reference issuance rather than promising constant storage scan cost. Discovery issues only returned object references. Oversized projections roll back their reference allocations and return unavailable/budget. Revocation, quarantine or grant updates delete the affected agent namespace immediately.

Typed native correction in this implementation accepts an exact live claim ID whose meaning is a positive literal assertion about a qualified supplied subject or an attested occurrence subject, with explicit asserted perspective and no roles or context. It preserves the owner's complete literal statement, records an independently attributable native support, and supersedes the old target atomically with insertion. An occurrence correction retains the exact prior occurrence identity through its immutable native target attestation; it does not mint a replacement identity from the owner's text or retain the erased source's occurrence snapshot. Nonliteral replacement and contextual/perspective edits require a richer correction request and remain open launch requirements; they fail before a native event is recorded. Typed neutral parents are excluded from the existing v1 canon materialization queue. A qualified typed canon renderer remains a separate launch requirement.

Qualified supplied references use the exact closed shape `{kind:"supplied",id,namespace:{connector_id,source_key}}`, preserving the original subject ID and its immutable event witness. Event subject IDs are only local to their connector/source namespace. Namespace participates in semantic keys and exact handle binding; equal spelling across sources never merges identities. Legacy two-field supplied references keep historical decoding and key bytes, but cannot qualify for new world admissions. Occurrence references retain their two-field shape and independently verified mint tuple. A native targeted correction records an immutable `metadata.world_target` attestation containing prior claim ID, prior semantic key, qualified subject and predicate; Core proves the live target during admission, and restore validates the immutable attestation without requiring a purged predecessor. This is a proposed implementation contract evolution, not evidence that older v2 supplied data had namespace proof.

Public world cards expose opaque claim references. `correct` additionally accepts the exact additive target `{world_claim:{kind:"claim",token}}`; legacy `claim_id`, `claim_key`, and `subject` targets remain compatible. `kizuki tell --world-claim TOKEN` exposes the same owner-scoped path, while `--claim` retains its existing raw-ID compatibility. During the existing gated mutation, Core resolves that token only in the caller's freshly current principal namespace, converts it to an internal claim ID, and then applies the existing source, grant, relay, authority, and live-claim checks through the typed correction writer. For a typed literal correction, an optional `object` must equal `statement`, because the immutable native assertion is the owner's literal statement. A token is never authority: stale, cross-principal, narrowed, and erased tokens return the same no-live-claim refusal; a still-resolvable token whose source was revoked takes the ordinary source-authorization refusal. All refusal paths precede native evidence recording.

Producer-v2 preserves D20's optional configured System One admission after extraction and before returning drafts to the writer. The judge receives complete typed assertions, request-local mentions and supplied handles, and their quoted evidence. A missing, malformed or unavailable configured judge cannot become an empty keep. Host-generated dropped items add the closed `systemone_rejected` reason with the local draft ID; the model response codec is unchanged. Unconfigured vaults continue ordinary extraction. This does not claim real-provider qualification.
