# World schema plumbing

Ledger migrations for the world model are additive. A new table declares a class and a spec, and backup, restore, integrity, purge and rebuild follow from that declaration. No migration edits the backup code.

## Table classes

| Class | Exported | After restore | `kizuki rebuild --layer world` | Purge |
| --- | --- | --- | --- | --- |
| authority | yes, one `world/<table>.jsonl` stream | rows restored | untouched | erased with its source |
| bookkeeping | yes, same stream | rows restored | untouched | erased with its source |
| derived | never | empty | cleared | erased with its source |
| cache | never | reinitialised | reinitialised | erased with its source |

A stream is written when the table's `since` is at or below the ledger version of the backup. Restore requires that stream, so an older archive that predates the table still restores. A stream that no registered table names is refused, never dropped.

## Table spec

`packages/core/src/world/tables/registry.ts` holds `WORLD_TABLE_SPECS`, parents before children. A spec carries:

- `name`, `class` and `columns` (every column, in export order);
- `since`, the ledger version whose migration creates the table, read from `WORLD_MIGRATION_VERSIONS`;
- `erasure`, how purge reaches the rows: a `cascade` foreign key to a named parent, named `trigger`s, or `none` with a reason;
- `create`, idempotent DDL for the table and its triggers, called by the migration and by restore;
- `reset`, an optional initial state for derived and cache tables. The default creates the table and deletes every row.

`assertWorldTableSchema` runs inside the ledger integrity check for every table past the frozen ledger 32 set. It fails when the table, a column, the cascade foreign key or a named trigger is missing.

## Migration numbers

`packages/core/src/world/tables/versions.ts` is the only file that holds migration numbers above the base. A schema packet adds one line under its own `// slot: <key>` marker, then reads `WORLD_MIGRATION_VERSIONS.<key>` in `ledger/db.ts` and in its table module. Numbers are contiguous from `WORLD_MIGRATION_BASE + 1` in merge order. If another migration lands first, add its count to the base and to every entry in one commit. Tests fail on a duplicate, a gap, a deleted slot marker, or a numeric literal for one of these versions anywhere else in the source.

## Backup range

The accepted backup ledger versions come from the migration list. A v3 archive is accepted from ledger 16 up to the current ledger, with 21 as the first v3-only version. An archive newer than the current ledger is refused with `backup ledger schema N is newer than M`.

## Rebuild

`kizuki rebuild --layer world` puts every derived and cache world table back in its initial state inside one transaction and prints the tables it reset. It never touches authority or bookkeeping tables, search or graph, and it takes no `--port` or budget option.

## Background jobs

`packages/core/src/serve/world-jobs.ts` holds `WORLD_JOBS`. The sync pass runs each job once, in order, after extraction and before canon writing. A job owns its transactions, does not hold the canon writer across a model request, and reads `stopRequested` between bounded units. A thrown error degrades the pass as `world_job:<id>:<message>` and the next job still runs. With no registered job the pass behaves as it did before.
