# Proposed decision rows for the world-model expansion

Status: **Draft for the owner. Nothing here is recorded.** These rows are proposals written on 2026-09-29 so the owner can accept, change or reject each one. An agent never edits `docs/decision-log.md`: the owner copies an accepted row into the log, assigns its `D` number and date, and only then moves an RFC status line. The ids below (`PD-...`) are drafting labels that the owner replaces.

Each row uses the shape of the [decision log](../decision-log.md): an id, a date, a title and the proposal. Where a row blocks work, the text says which. The amendments these rows record are in the [RFC 0004 amendment record](../../rfcs/0004-living-epistemic-world-model.md#amendments), and the contracts they rely on are in [Appendix B](../../rfcs/0004-domain-contracts.md).

## How each row relates to the binding decisions

Every proposal keeps D9 to D18 and D22 as they are. None of them adds an owner review queue, an owner approval step or owner labeling of sensitivity (D9, D10, D11). None makes canon writing work without a model (D12). None puts retrieval inside core (D13, D17). None adds an MCP write tool: the tool count stays ten and the write tools stay `propose` and `correct` (D14). None widens the inert public grant (D18).

## Not decisions

Deploying a build, configuring a model, enabling a schedule and the production upgrade from the current ledger version to the final one are owner operations under a separate authorization. They are not rows in the decision log and nothing here authorizes them.
