# Golden journey

Evidence date: 2026-10-21. The executable common journey uses the real App host,
real source capture and writer, and two independent MCP stdio processes on one
disposable vault. Its model endpoint is a deterministic synthetic fixture. This
proves integration; it does not qualify extraction-model quality or activate new
producer vocabulary.

## Run the common journey

```bash
bun test packages/mcp/test/golden-journey.test.ts
bun run typecheck
```

The two variants exercise default envelope v2 and owner legacy-tool v1
compatibility. `world_view` requires v2 in both: the second run explicitly proves
`context_packet` still supports the owner's v1 contract before negotiating v2
for world operations. Scoped clients always use v2.

The source file explicitly cites its own filename. The Markdown connector's
structured document subject can therefore supply a real, source-qualified handle
anchored in the text across file revisions. The fake never invents a supplied
handle or inserts claims directly. The App first captures with local-only
consent; the test proves that pass makes no source-model request, then grants the
exact selected model destination and runs the actual extraction writer.

The journey checks source event and canon receipts, cross-principal resume,
quoted evidence spans, audit records for both clients, and a real consolidation
HTTP response held while the new source assertion is already readable. Both
clients must return pending consolidation or stale dependencies during that
window, never an old summary marked current. Compatible definitions remain
separate assertions under `valid: all`; a separate explicit owner correction
replaces exactly its target, remains visible to both readers, preserves the saved
historical view, and reverses through its receipt.

Grant narrowing invalidates the scoped client's retained view, resume handle
and known snapshot. Old evidence resolves without exposing the source. The owner
positive control remains readable. Supported world rebuild and backup/restore
preserve fresh readable assertions while invalidating old capabilities; snapshots
exclude agent credentials and require fresh enrollment. Finally, source
revocation removes access and physical erasure deletes source event payload,
claim-v2 support and derived summaries. Source-binding tombstones remain as audit
metadata. A separately restored copy or an older external backup is outside the
original vault's purge operation.
