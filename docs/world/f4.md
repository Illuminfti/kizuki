# World vocabulary registry and write-time enforcement

Status: implemented on the ocean integration branch. Evidence date: 2026-09-29.

This page describes how the world vocabulary is registered and how the shared
claim writer enforces it. It does not change `kizuki.world-vocabulary/v1`: the
schema id and every existing predicate row are pinned by a test.

## What a kind is

A kind is data. `WorldKindSpec` in `packages/core/src/contracts/world-kinds.ts`
holds the kind id, the `world.kind` value that classifies a subject as it, its
label predicate, the vault page type its canon page carries, its endpoint kind,
its card schema, whether the extraction model is told about it, and the paths by
which claims of the kind can exist (`extraction`, `owner_assertion`,
`derived`).

Each kind lives in one vocabulary module under
`packages/core/src/contracts/world-vocab/`. The module owns the kind and its
predicate rows. Concept and situation are modules today. The learning
predicates are a kindless module: they add rows about people and concepts and
say for themselves whether they are offered to the extraction model.

`world.kind` is never written by hand. Its allowed values are derived from the
registered kinds, so a kind cannot exist without its classification value.

## Adding a kind

1. Add `contracts/world-vocab/<kind>.ts` exporting a `WorldVocabularyModule`.
2. Add one line under your marker in `WORLD_VOCABULARY_MODULES`
   (`// slot: quest`, `people`, `skill`, `sit2`, `art`, `ident`).
3. Register with `offeredToProducer: false`. The extraction prompt stays
   byte-identical until a held-out extraction check justifies flipping it.

Registration is checked once when the module is loaded: duplicate kind ids,
duplicate predicates, a hand-written `world.kind`, a missing or non-literal
label predicate, and a classification id outside `world/` all throw.

## What the writer refuses

`validateWorldAssertionAgainstRegistry` runs inside `commitClaimV2`, the child
of the one shared claim writer, for every world assertion whose predicate is in
the vocabulary. Refusals carry a deterministic `ClaimError` code, checked in
this order:

| Code | Meaning |
| --- | --- |
| `world_object_kind` | The object is a literal, a vocabulary value or a subject that the row does not allow. |
| `world_vocabulary_value` | A closed value list (`world.kind`, `learning.assistance`) does not contain the value. |
| `world_polarity` | The row does not list the assertion's polarity. |
| `world_endpoint_kind` | A subject or typed object is already classified as a different kind. |

A refused write rolls back with the rest of its transaction, so no claim row is
left behind.

Classification is claim-derived, so the check never depends on arrival order.
An endpoint with no classification yet is accepted. Only a contradiction with a
known classification is refused. A known classification is a live, positive,
asserted `world.kind` claim whose value is a registered kind. A hypothetical or
negative classification does not count. A card or discovery result appears only
once its subject is classified.

Claims stored before enforcement stay readable. The read side does not run this
check. Re-asserting a claim that violates its row is refused, and the stored
claim is left alone.

## Extraction

The extraction model is shown the predicates and vocabulary values of offered
kinds only. With every shipped kind offered, the input is byte-identical to
before (pinned by hash). Flipping a kind's flag adds exactly its predicates and
its classification value.

A model draft that the writer would refuse is dropped as `invalid_claim` when
the decision is journaled, in filing order and seeing the classifications
before it in the same batch. Without this a single contradictory draft would
make a durable decision fail at filing on every pass.

## Honest fallbacks

A kind registered but not offered to the extraction model has
`population: ["extraction"]` and `offeredToProducer: false`. Discovery and any
describe surface can read those two fields to report that the kind is empty by
design instead of claiming coverage. This change adds no read surface for that
report.
