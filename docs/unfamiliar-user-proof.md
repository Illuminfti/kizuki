# Unfamiliar-user proof protocol

Evidence date: 5 September 2026. This is a protocol for an authorized future
human run. No trusted participant/witness evidence adapter is implemented.
Completing a template, writing a participant name or checking a box cannot
make the [release acceptance checker](release-acceptance.md) accept this gate.

The timed milestone is a non-author on a fresh machine reaching autonomous
model-written canon and an authorized agent query within fifteen real minutes,
with zero coaching. A visible provenance receipt and working undo must also
be demonstrated and timed separately if they occur after that milestone.
Lifecycle and clean-target recovery are additional obligations; their time
does not silently redefine the fifteen-minute milestone.

## Prepare an authorized attempt

Freeze the exact native package, source SHA, both executable hashes, package
checksums and public installation instructions. Record the supported native
platform and architecture. A Linux attempt does not qualify macOS.

The participant must not have authored or implemented the product. A reviewed
evidence process must independently establish participant and witness
eligibility; a self-declared role is insufficient. The participant may use the
published instructions and built-in help. An author, agent or witness must
not operate the session or supply missing setup instructions.

Before accessing a source, record the applicable participant authorization
for the precise account, fields, history scope and destinations. Record the
chosen model endpoint and any approved cost ceiling. Never treat this runbook
as authority to enroll an account, incur cost or alter a service. A provider
application prepared in advance must be part of documented shipped setup,
not hidden author assistance.

Use a genuinely fresh host or user profile with no Kizuki configuration,
preloaded vault or undisclosed credentials. The scripted clean-home artifact
proof is useful prerequisite evidence; it does not identify the person
operating a session. Retain private source/account evidence outside the
repository and expose only the bounded references needed for review.

## Observe the participant

1. Record actual wall and monotonic start time when the participant receives
   the package and instructions. Do not backdate, pause away setup difficulty
   or reset a failed attempt's timer.
2. Let the participant install to a stable path and follow normal `init`.
   Observe actual supervisor installation, activity and enablement. The
   artifact proof's `--no-service` path does not satisfy this step.
3. Let the participant connect the agreed source and give source/model
   consent through the normal product. Verify ingestion and autonomous
   model-written canon from that scope. Capture bounded receipt identifiers
   and before/after hashes without publishing source text or secrets.
4. Observe an authorized agent query returning the resulting knowledge.
   Record the real elapsed milestone and whether it was within 900000 ms.
   A model-free ledger query alone does not demonstrate loop-written canon.
5. Ask the participant for their usefulness judgment through the approved
   witness process. Local fixture content may qualify a narrower usability
   exercise, but cannot prove live-account access or normal-week usefulness.
6. Observe conversational correction and the resulting canon, query/context
   and receipt behavior. Demonstrate audit and undo, retaining their distinct
   observation times and outcomes. No canon approval queue is involved.
7. Observe backup and a clean-target restore, then verify query and context
   against the restored content. Record failures and unresolved losses.

If help, manual rescue or author intervention occurs, record it immediately.
That attempt fails the zero-coaching requirement. A later attempt has a new
identifier and retains the earlier failure; it does not erase or relabel it.
Record timer interruption or ambiguous evidence as unresolved rather than
estimating a passing duration.

## Verify native lifecycle separately

In an explicitly authorized disposable user-service environment, retain
native receipts for installation from the stable executable path, upgrade,
restart, reboot and uninstall. Verify pending lifecycle-intent recovery and
vault preservation. Perform the platform obligations on both Linux x64 and
macOS arm64. Cross compilation, fake supervisors, a generated plist,
`serve --once` and a successful query do not establish these behaviors.

The human timed attempt and native lifecycle receipts can refer to the same
frozen candidate, but neither substitutes for the other. A later binary change
must not silently inherit acceptance from the earlier attempt.

## Retain a review record

This blank record is a collection aid, not an executable receipt or authority
grant. Keep identities and account details in the separately approved private
evidence process. Do not commit credentials, private endpoints, raw prompts,
source records or unrestricted session recordings.

| Observation | Retained reference or unresolved result |
| --- | --- |
| Attempt identifier and prior attempts | Unrecorded |
| Candidate SHA, target and five package hashes | Unrecorded |
| Frozen public instructions | Unrecorded |
| Participant and independent witness eligibility | Trusted evidence source unavailable |
| Fresh machine/profile evidence | Unrecorded |
| Exact source/model scope and applicable authorization | Unrecorded |
| Real start wall and monotonic time | Unrecorded |
| Normal init and supervisor observation | Unrecorded |
| Ingestion and autonomous canon receipt | Unrecorded |
| Agent query and elapsed timed milestone | Unrecorded |
| Coaching, intervention and all failures | Unrecorded |
| Participant usefulness disposition | Trusted evidence source unavailable |
| Correction, receipt and undo times/results | Unrecorded |
| Backup and clean-target restore | Unrecorded |
| Both native lifecycle receipt references | Unrecorded |
| Independent disposition and unresolved findings | Trusted evidence source unavailable |

No field defaults to pass. The reviewer must retain complete attempts and
resolve contradictions through the future trusted evidence process. The
acceptance checker continues to report this gate as `NOT_IMPLEMENTED` until
that producer and its authority bindings have been reviewed and implemented.

## Verify the record

Check package identity against the [native artifact proof](native-build.md),
retain exact timing evidence and failed attempts, and verify every claimed
consumer behavior through its receipt. Keep the timed result, correction/undo,
restore and native lifecycle outcomes distinct. Do not infer the required
normal-week, seven-day owner or fourteen-day estate evidence from this attempt.

The day-seven estate review and final cutover authority remain operational
requirements in the [binding decisions](decision-log.md). They do not make
the owner review or promote canon.
