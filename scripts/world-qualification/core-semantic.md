# Core11 prospective semantic corpus

Authored 2026-10-22 as twelve neutral, synthetic qualification cases: direct,
person-reported and explicitly historical positives, plus name-only, blank-template
and hypothetical zero-claim negatives, for both Concept and Situation.

The twelve source records, required atoms and witnesses are newly authored facts.
This is prospective evidence authored after the generic literal instruction was
frozen; it is not a strict-blind independently selected benchmark. No candidate
response, model run, provider, account, private output, vault or runtime data was
accessed during authoring. Prior Core10 material was read only for schema and
freshness comparison. The rejected earlier Core11 scaffold was not read or reused.

The fixed v2 contract policy is copied by programmatic deep copy from source
commit `59018795af12da4ea691c1a4275b276a91df626d`. Only `cases` and the
campaign identifier `corpus_version` differ in the contract. Corpus `version`
changes to match. Canonical policy comparison explicitly excludes only `cases`
and `corpus_version`; all remaining fields must match. There are no label
alternatives and no inferred or widened temporal allowances.

Direct classification headers stand outside reported quotations. Every historical
classification header and every reported detail is explicitly scoped to the same
exclusive-ended interval, without asserting the referent's entire lifespan. Each
positive source record is at most 400 decoded characters, including roles and
historical bounds. Each required meaning atom is entailed by its one declared
literal witness. Person reporting retains its supplied ref or exact unique
occurrence alternative as explicitly declared; document reporting retains its
supplied document ref.

The already-frozen generic explicit-literal instruction was supplied by the
orchestrator as SHA256
`67cb33866efff0c8d717744465bd52052108f0ffb7f499cb10a3440fe66f1f32`,
with code commit `cdd29ed8fd083f8c9aa553a70345f1925263485b`. Those values are
provenance supplied to this author, not a claim that this author inspected the
prompt or code. No prompt, evaluator, parser or guard was modified.

## Verification

`validate.py` checks source pins, exact non-case policy equality, ordered coverage,
source roles, unique witnesses, direct quotation boundaries, exclusive intervals,
400-character bounds, negative structure and lexical freshness against the supplied
Core10 assets. `validate-source-function.ts` executes the exact unmodified
production asset-validation function extracted from the pinned source against
these local files. These are asset checks, not a model qualification result.

`validation.json`, `authorship.json`, `secret-scan.json` and `freeze.json` record
authoring, local checks and SHA256 content pins. Every finalized file is made
read-only. Independent review remains required before any model call; no model
quality or qualification result is claimed here.

Active execution and quote-resolution custody follow [Core semantic v3](core-semantic-v3.md). The prospective case records and expectations are unchanged by the method adaptation.
